how it works

Cleanvim has about 1,900 lines of Lua. This page walks through every part, so you know which file to open.

home github

startup

init.lua loads four modules, in this order:

  1. config/defaults.lua sets the leader key and loads your saved state (theme, transparency, diagnostics, format-on-save).
  2. core/ sets options, keymaps and autocmds. These use only Neovim itself, with no plugins.
  3. lazy.lua installs lazy.nvim on first launch and loads every spec under plugins/.
  4. ui/ applies the saved theme, transparency and diagnostic style.

Startup takes about 25 ms. Most plugins wait until something needs them:

startupoil, lualine, treesitter, mini.cmdline
VeryLazywhich-key, mini.ai / pairs / surround / bracketed, indent guides
open fileLSP, mason, conform, nvim-lint, gitsigns, code context
insertblink.cmp
keypresstelescope, harpoon, trouble, undotree, fugitive, dap
colorschemeonly the theme you use

state

Anything you switch or toggle is saved to ~/.local/state/nvim/cleanvim.json, outside the repo. This keeps your clone clean, so git pull never conflicts with your settings. The file is config/state.lua, about 30 lines.

add · switch · toggle

These are small modules in plugins/builtin/. They load once lazy.nvim finishes.

add ␣a…

Opens the matching folder (custom plugins, themes, languages, snippets) in a floating oil window. Create a file there and it's picked up on the next start.

switch ␣s…

A telescope picker. The theme switcher previews each theme as you move through the list. Enter saves it, and Esc goes back to the one you had.

toggle ␣t…

Flips a setting right away and saves it if it should last: transparency, format on save, languages. Spelling, grammar, mouse and inlay hints last only for the session.

languages

Each language is one file in lua/cleanvim/languages/:

return {
    mason = { "gopls", "gofumpt" },       -- first entry is the LSP
    formatters = { go = { "gofumpt" } },  -- conform
    linters = {},                         -- nvim-lint
}

␣tl lists every file. When you turn a language on, Mason installs its packages and its language server starts on its own. When you turn one off, its server stops and Cleanvim uninstalls any package that no other enabled language uses. A fresh install starts with only Lua and Bash.

lsp

  1. Mason installs servers and puts them on PATH.
  2. mason-lspconfig calls Neovim's own vim.lsp.enable() for each installed server.
  3. blink.cmp adds completion capabilities to every server through vim.lsp.config("*").
  4. When a server attaches to a buffer, LspAttach sets that buffer's keys (gd, K, ␣rn, ␣ca…). Buffers without a server keep Vim's built-in gd and K.

Grammar checking (␣tg) uses harper-ls. It starts off and installs the first time you turn it on.

syntax

No parsers are compiled up front. Neovim already ships parsers for C, Lua, Markdown, Vim and its help files. When you open any other filetype, an autocmd in core/autocmd.lua installs its parser and turns highlighting on.

formatting & linting

conform formats with the tools from the language files, and falls back to the LSP when no tool is installed. Format-on-save checks a flag each time you save, so ␣tfs takes effect right away. nvim-lint runs only the linters that are actually installed.

your own stuff

Files in plugins/custom/ are git-ignored lazy.nvim specs, so they survive updates. To change a core option or key, edit core/ directly. Each file is short enough to read in a minute.

updating

git pull              # latest
git checkout v0.1.0   # stay on a release

Every push runs CI: formatting (stylua), linting (selene) and a headless start that fails on any error.
